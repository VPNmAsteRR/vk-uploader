# vkup — загрузка видео в VK без токенов и API

Локальный инструмент: ставишь файлы в очередь, он по одному загружает их в VK
**через настоящий браузер** — так, как это делал бы ты сам руками.

- **Никакого API и токенов.** Работает с обычной залогиненной сессией в Chromium.
- **Демо-режим** для проверки на своей машине: полный цикл, но загрузка идёт на
  локальную страницу-заглушку. Ничего не уходит в сеть.
- **Очередь** с прогрессом, паузами, повторами, отменой и журналом.
- **Приватность:** сервер слушает только `127.0.0.1`, файлы никуда не отправляются,
  кроме страницы загрузки, которую ты сам открыл.

Для тех, кому не нужны исходники и Python — готовый exe:

## Быстрый старт (демо, безопасно)

```bash
cd vk-uploader
../venv/bin/python vkup.py --backend demo
```

Открой <http://127.0.0.1:8765/>, нажми **Старт**, добавь видео — увидишь, как
работает очередь, прогресс, повторы и журнал. Загрузка уходит на локальную
страницу `/mockvk/upload`, реальный VK не затрагивается.

Файл с `fail` в имени специально провалится — удобно проверять повторы.

## Проверка на своём VK

1. Переключи режим: **Настройки → Режим работы → Боевой** (или запусти с
   `--backend browser`).
2. Нажми **«Открыть браузер»**. Откроется Chromium с отдельным профилем.
   Это первый запуск — войди в VK руками (и QR, и пароль — как обычно).
3. Нажми **«Проверить вход»** — должно стать «вход подтверждён».
   Сессия сохраняется в профиле, поэтому больше логиниться не придётся.
4. Добавь видео и жми **Старт**.

## Если VK поменяет вёрстку

Два инструмента, чтобы починить за пару минут:

- **Диагностика → Проверить селекторы** — покажет, какие элементы нашлись,
  какие скрыты и какой текст у них.
- **Диагностика → Показать элементы страницы** — выведет все поля, кнопки и
  чекбоксы с готовыми CSS-селекторами.
- **Селекторы** — вставь найденный селектор в нужное поле (по одному в строке).
  Твои строки пробуются первыми, встроенные остаются как запасные.

## Что внутри

```
vk-uploader/
  vkup.py                 запуск
  vkup/
    server.py             локальный HTTP + JSON API + раздача интерфейса
    browser.py            Selenium: браузер, вход, загрузка, диагностика
    engine.py             очередь: воркер, повторы, отмена
    db.py                 SQLite: задания и журнал
    selectors.py          селекторы страницы (можно переопределять)
    config.py             настройки (data/config.json)
  web/
    index.html, app.js, app.css    интерфейс
    mock_upload.html               локальная страница-заглушка
  bas/                     проект для Browser Automation Studio
    vk_video_upload.xml    открыть в BAS
    build_bas.py           генератор (селекторы и настройки)
    check_bas.py           проверка синтаксиса
    simulate_bas.py        прогон логики
    verify_selectors.py    проверка селекторов в Chromium
    README.md              инструкция по BAS
  tests/test_vkup.py      автотесты (реально запускают Chromium)
```

## Версия для Browser Automation Studio

Если нужен не веб-интерфейс, а **скрипт для BAS** — он лежит в `bas/`.
Открывается в BAS через «Файл → Открыть проект». Работает так же: список
файлов → очередь → загрузка → повторы → отчёт. Подробности и инструкция по
проверке: [`bas/README.md`](bas/README.md).

## Требования

- Linux (проверено на Arch), Python 3.11+
- `chromium` (или Chrome) и `chromedriver` в PATH
- `selenium` (уже стоит в общем `venv`)
- `ffprobe` — необязательно, нужен только для длительности/разрешения

## Настройки

Все параметры — в интерфейсе (**Настройки**) и в `data/config.json`:

| Параметр | Смысл |
|---|---|
| `backend` | `demo` — локальная заглушка, `browser` — реальный VK |
| `headless` | без окна; **мешает входу**, включай только после входа |
| `profile_dir` | профиль Chromium, где живёт сессия VK |
| `upload_url` | страница загрузки (по умолчанию `https://vk.com/video?act=upload`) |
| `max_attempts` | сколько раз пробовать файл |
| `retry_base_delay` | пауза перед повтором (дальше удваивается) |
| `workers` | всегда 1: несколько окон браузера мешают друг другу |
| `delete_after_upload` | удалить исходник после успеха |
| `skip_duplicates` | не ставить один и тот же файл дважды (по SHA-256) |

Тесты (реально запускают Chromium, ~50 с):

```bash
../venv/bin/python -m unittest discover -s tests -v
```

13 тестов: полный цикл загрузки в реальном браузере, повторы при ошибке,
дедупликация, отмена, отсутствующий/пустой файл, пакетная загрузка, HTTP API,
безопасность путей.

## Ограничения

- Один браузер = одна загрузка за раз. Это не «ферма», а аккуратный помощник.
- VK может показать капчу или потребовать подтверждение — тогда инструмент
  останавливается и пишет об этом, а не пытается обойти защиту.
- Интерфейс VK меняется; для этого и сделаны «Селекторы» + «Диагностика».
- Инструмент не обходит ограничения VK и не работает с чужими аккаунтами —
  только твоя сессия, твои видео.

## Что делать, если что-то не так

- **«нужен вход в VK»** — «Открыть браузер», войди, «Проверить вход».
- **«не нашёл поле выбора файла»** — «Диагностика → Показать элементы страницы»,
  скопируй селектор поля файла в «Селекторы».
- **Загрузка висит** — посмотри «Скриншот» в журнале: там будет текущее состояние
  страницы. Часто это капча или изменившаяся кнопка.
- **Не запускается браузер** — проверь пути к `chromium` и `chromedriver`
  в настройках (`/usr/bin/chromium`, `/usr/bin/chromedriver` на Arch).
